# ADR 0001: 改用 Deepgram Nova-3 一次完成轉錄與講者分離，取代 Groq Whisper

## Status

Accepted（2026-09-26）。「語言固定指定 `zh-TW`」已被 ADR 0002 局部取代：語言改成上傳時選（預設仍是 `zh-TW`）。

## Context

講者分離（見 `.scratch/speaker-diarization/spec.md`）需要知道「每個字是誰說的」。目前的 Groq Whisper 只做轉錄，沒有講者分離；2026-09-25 的研究排除了其他路線：Hugging Face Inference Providers 沒有服務在提供講者分離，自己架 pyannote 在 Render 免費層跑不動（記憶體峰值約 1.5GB）。剩下兩條路：

1. **Deepgram Nova-3**：一次呼叫同時完成轉錄和講者分離，講者標籤精確到每個字。
2. **Groq Whisper（逐字時間戳）+ pyannoteAI（exclusive 模式）**：兩家各做一半，再用最大重疊把講者對到每個字上。

spec 事先定好決策規則：**Deepgram 的中文準確度不比 Whisper 差 → 改用 Deepgram；否則走 Groq + pyannoteAI。**

### 實測（2026-09-26）

拿四段公開的台灣中文 podcast 片段（2026-09 的最新集數，各擷取 3～4 分鐘，轉成單聲道 16kHz 64kbps mp3，音檔只放在本機暫存、沒有進版控），分別送進：

- Groq `whisper-large-v3-turbo`（現行設定：`verbose_json`，另外多要了逐字時間戳，給 pyannoteAI 路線評估用）
- Deepgram `nova-3`（`language=zh-TW`、`diarize`、`smart_format`、`punctuate`）
- 順便也跑了 Deepgram `nova-2` 當對照

| 片段 | 內容 | 講者 | Groq | Nova-3 |
| --- | --- | --- | --- | --- |
| 單人 | 主持人獨白業配 | 1 | 1.0 秒 | 2.9 秒 |
| 雙主持人 | 閒聊夾業配，常互相插話 | 2 | 1.6 秒 | 2.4 秒 |
| 訪談 | 主持人訪問來賓，一問一答 | 2 | 1.2 秒 | 2.5 秒 |
| 政論 | 來賓長篇講述，兩位主持人插話 | 3 | 1.7 秒 | 2.5 秒 |

（時間是 API 回應時間；兩家對幾分鐘的音檔都只要幾秒，處理時間不會是選擇的依據。）

**沒有人工校對的參考稿。** ticket 原本要求對人工參考稿算錯字，但這次沒有人可以校對。改用下面的做法，比較粗，但判斷方向很一致：把兩邊結果逐段對照，只看有分歧的地方，依上下文判斷哪一邊是對的。

**錯字（有分歧的地方）：**

- Nova-3 比較對的：專有名詞和一般用詞明顯較好——「電商」（Groq：電傷）、「歐卡桑」（歐卡商）、「木耳飲」（木耳營）、「手搖店」（手搖電視）、「底定」（敌定）、「吸引力法則」（吸引你一法則）、「造就」（照舊）、「宋少卿」（宋少青）、「沾在上面」（站在上面）、「導熱」（導溫）。
- Groq 比較對的：少數口語片語——「其實我想一下」（Nova-3：雞我想一下）、「你根本可能還在當老師」（你幹嘛可能…）、「叫他不要在酒駕」（9號不要在酒駕）。
- Nova-3 偶爾整句漏掉（例如訪談裡的「四歲你就追不到」），但 Groq 也有自己的問題：政論片段有 40 個片段的長度剛好是 1.00 秒，是在沒有可靠對齊時硬湊的時間戳，會讓播放同步和字幕對不準。
- 結論：**Nova-3 的中文準確度不比 Groq 差**，專有名詞甚至更好。

**講者歸屬（只有 Nova-3 評得出來）：**

- 較長的輪流發言（訪談的一問一答、主持人長段提問）大致正確，但換人的邊界常常差幾個字（例如「…對所以你｜胖到120公斤…」）。
- 很短的插話（「真的」「對」「你有練過相聲？」）常被併進前一位講者。三人政論只分出 2 位講者，兩位主持人的插話幾乎都被歸給來賓。
- 同一段音檔只切 32 秒送出時，短插話反而分得比較好——講者分離的品質會受上下文長度影響。
- 這個品質對「重點是看出誰講了哪一大段」的逐字稿來說夠用；更精確的歸屬要靠 spec 裡的「指定片段講者」手動修正（ticket 05）。
- pyannoteAI 路線沒有實測：決策規則只看轉錄準確度，而 Nova-3 已經達標。

**其他發現：**

- **繁體輸出**：Nova-3 `zh-TW` 絕大部分是繁體，但會漏出簡體（單人片段開頭一整句都是簡體，s2tw 轉換改了 14 字；其他片段 1～8 字）。Groq 簡繁混雜（改了 1～177 字）。**所以既有的 OpenCC s2tw 轉換要保留**，不能因為要求了 `zh-TW` 就拿掉。
- **中文沒有標點**：兩家都幾乎不輸出中文標點（Nova-3 就算開了 `punctuate`/`smart_format`，四段加起來只有 1 個標點）。spec 設計的「句末標點就切片段」對中文幾乎不會發生，只靠「換人」和「15 秒強制切」會切出很長的片段。模擬結果：再加一條**「字與字之間停頓 ≥ 0.5 秒就切」**，片段長度中位數約 3 秒，15 秒強制切一段錄音只會發生 3～6 次。
- **數字與英文被切碎**：`smart_format` 對中文裡的數字和英文會切成奇怪的 token（「200」「3年」、「h」「app」「y」），Deepgram 自己的 `transcript` 欄位接起來是「200 3年」「h app y」。這是廠商的切法，不另外修正；片段文字照 spec 的串接規則處理（中文之間不加空白、英文之間加一個空白）。
- **不能讓它自動偵測語言**：改用 `detect_language=true`（不指定語言）時，Deepgram 偵測出 `zh`，但走的是通用中文模型：輸出簡體，錯字也明顯變多（同一段的「黃立成」變成「黃歷程」、「木耳飲」變成「木耳影」）。
- **Nova-2 明顯較差**：常整段漏字，也有重複幻覺（「對本來都是直營的對不對」連續重複 4 次），不考慮。
- **重新確認 2026-09-25 的事實**（deepgram.com/pricing，2026-09-26）：新帳號 $200 免費額度、不用綁卡；講者分離包含在預錄音檔的價格裡，不另外收費；Nova-3 單一語言 $0.0043/分鐘（= $0.258/小時），跟研究時一致。講者標籤確實精確到每個字（每個字都有 `speaker` 和 `speaker_confidence`）。

## Decision

**用 Deepgram Nova-3 取代 Groq Whisper**，一次呼叫同時完成轉錄和講者分離（`model=nova-3`、`language=zh-TW`、`diarize=true`、`smart_format=true`、`punctuate=true`）。

- 呼叫包在不綁定廠商的 adapter 後面（spec 的「偵測到的語言 + 逐字資料」格式），之後要換廠商只換 adapter。
- 片段切分除了 spec 原本的「換人、句末標點、約 15 秒強制切」之外，**再加上「字與字之間停頓 ≥ 0.5 秒就切」**，因為中文轉錄實際上不會有標點。
- 語言固定指定 `zh-TW`（設定 `DEEPGRAM_LANGUAGE`），不自動偵測。
- 轉錄結果照舊經過 OpenCC s2tw 轉成繁體。
- 「是不是暫時性錯誤」的判斷改成 Deepgram 版（429、5xx、逾時算暫時性），Groq 專用的判斷一起移除。
- 測試用的 fixture 是一段 32 秒訪談片段的**真實** Nova-3 回應（`tests/fixtures/`），內容是公開 podcast 的日常對話，沒有敏感內容；裡面有 4 次換人，以及一個只有一個字就換講者的情況，可以用來測試切片段的邊界。

## Consequences

- **被否決的選項**：
  - *Groq + pyannoteAI*：多一家廠商、多一次呼叫、還要自己用最大重疊合併；pyannoteAI 試用 1 個月後每月最少 €19。在 Nova-3 準確度已經達標的前提下，這些成本沒有必要。
  - *Deepgram Nova-2*：漏字和重複幻覺太多。
  - *自己架 pyannote*：Render 免費層記憶體不夠。
- **額度是一次性的**：$200 用完就要付費（每小時 $0.258，約 775 小時的音檔），不像 Groq 每天重置。專案目前沒有額度監控和告警（架構文件第 7 節已經列為缺口），寫進 README 的已知限制。
- **Groq 的前提跟著消失**：upload-service ADR 0001 的「AUDIO 上傳上限 20MB」是為了配合 Groq 的 25MB 上限。Deepgram 沒有這個限制，但要不要放寬另外開票評估，不在這裡處理。（2026-09-28 已放寬到 120MB，時長上限改 60 分鐘，見 upload-service ADR 0001 的修訂。）
- **非中文錄音會辨識得很差**：語言是固定指定的，Groq 原本會自動偵測語言，這是一個退步。產品的使用者和內容都以台灣中文為主，所以接受；真的需要時可以改設定，或之後再評估「先偵測、再用對應語言轉錄」（要多付一次費用）。（2026-09-28：改成上傳時選中文、英文或自動偵測，見 ADR 0002。）
- **講者歸屬不完美是已知的**：短插話常被歸錯人、偶爾分不出第三位講者。產品上靠重新命名講者和手動指定片段講者來修正，不追求自動分離完全正確。
- **片段會比 Groq 的長**：Groq 的片段大多 1～2 秒（一小句一個片段），新的切法中位數約 3 秒。播放同步和搜尋都以片段為單位，這個長度仍然可以用。
