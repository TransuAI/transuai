# frontend

音訊/影片逐字稿 + AI 分析平台的前端。React 19 + Vite + TypeScript + Tailwind CSS v4 + shadcn/ui。

對照 [`../infra/architecture-design.md`](../infra/architecture-design.md),對接 Gateway 的 REST API（`../gateway`)與 notification-service 的 WebSocket。

## 技術棧

| 項目 | 選擇 |
|---|---|
| 框架 | React 19 + Vite（`react-ts` 模板） |
| UI | Tailwind CSS v4 + shadcn/ui（Nova preset：Radix + Geist 字型） |
| 路由 | react-router-dom v7 |
| 狀態 | 沒有拉 Redux/Zustand,登入狀態用一個簡單的 `AuthContext`（`src/context/auth-context.tsx`），Job 資料用各頁面自己的 `useState`/`useEffect`,規模還不需要全域 data-fetching 套件 |
| API 呼叫 | 手刻的 `fetch` wrapper（`src/lib/api-client.ts`），處理 401 → 自動換發 access token（refresh token 在 gateway 設的 httpOnly cookie，JavaScript 讀不到；伺服器每次換發都會輪替）→ 重試一次；問答走 SSE（`requestSse`），不用原生 `EventSource`——它沒辦法附加 Authorization header，見 [`../docs/adr/0001-sse-via-gateway-for-streaming-qa.md`](../docs/adr/0001-sse-via-gateway-for-streaming-qa.md) |
| 即時更新 | 原生 `WebSocket`（`src/hooks/use-job-socket.ts`）直連 notification-service |

## 前置需求

需要先啟動後端(至少 Gateway + Auth + Upload,完整功能需要六個服務都起來,見 [`../infra/README.md`](../infra/README.md))：

```bash
cd ../infra
docker compose up -d
```

再依序啟動 `auth-service` / `upload-service` / `transcription-service` / `ai-service` / `notification-service` / `gateway`（各自 README 有說明）。

## 開發

```bash
cp .env.example .env   # 第一次使用才需要,預設值就能跑
npm install
npm run dev
```

### 測試

```bash
npm test
```

Vitest + React Testing Library + `jsdom`。頁面測試一律 mock `src/lib/api.ts`（或 `api-client.ts`）當作對外邊界,其餘透過使用者看得到的行為（文字、role、點擊）驅動,不測內部實作細節。不碰畫面也沒有 I/O 的純函式模組(例如 `lib/export-formats.ts`,規則組合多、直接比對輸出文字比透過頁面可靠)則直接測它的 export。設定在 `vite.config.ts` 的 `test` 欄位,共用的測試環境設定在 `src/test/setup.ts`。

`vite.config.ts` 把 `/api` proxy 到 `http://localhost:8080`（Gateway),所以本機開發預設 `VITE_API_BASE_URL=/api` 即可,不會有 CORS 問題。**API 一定要跟前端同源**(正式環境也是經反向代理的 `/api`):refresh token 的 cookie 是 `SameSite=Strict`(名稱 `__Host-refresh_token`),`VITE_API_BASE_URL` 設成別的網站的網址,重新整理頁面就會被登出(見 gateway README「refresh token 的 cookie」)。notification-service 的 WebSocket(`8085`)沒有走 Gateway,前端直連,見 `.env.example` 的 `VITE_WS_BASE_URL`。

### 部署包（nginx）

`Dockerfile` build 出 `transuai/frontend`：`npm run build` 的檔案由 nginx（`nginxinc/nginx-unprivileged`，不用 root）提供，同一個網站把 `/api/*`
（去掉 `/api`）轉給 gateway、`/ws/*` 轉給 notification-service（`nginx/default.conf.template`，啟動時用環境變數 `GATEWAY_URL`、`NOTIFICATION_URL`、
`STORAGE_ORIGIN`、`TRUSTED_PROXY_CIDR` 換掉）。頁面的安全標頭與 CSP 在 `nginx/page-headers.conf`；只提供 `/assets/` 的 `.js .css .woff2 .svg .png`
與 `favicon.svg`，其他路徑都給 `index.html`；SSE 不緩衝；請求本文最多 1MB。TLS 在前面那層做，範本是 `nginx/tls.conf.example`。kind 上是
`infra/k8s/26-frontend.yaml`（`kubectl -n transuai port-forward svc/frontend 8088:8080`）；開發照舊用 `npm run dev`。

### 環境變數

| 變數 | 預設值 | 說明 |
|---|---|---|
| `VITE_API_BASE_URL` | `/api` | Gateway REST base URL,dev 模式靠 vite proxy 轉發到 `localhost:8080` |
| `VITE_WS_BASE_URL` | 同一個網站（`ws(s)://<頁面的 host>`） | notification-service 的 WebSocket。預設走同一個網站的 `/ws`（開發時 Vite 轉到 `localhost:8085`，部署時前端的 nginx 轉）；要直連別的位址才設 |

```
src/
  components/
    ui/              shadcn/ui 元件(不手動改,要改用 npx shadcn add --overwrite)
    layout/          AppShell、Sidebar(導覽:我的檔案、決策、上傳、設定,管理員多一個「系統設定」;使用者選單;Job Detail 頁自動收成 icon rail)、深色模式切換

    job-status-badge.tsx
    model-credit.tsx       模型寫的東西下方的「由 AI 回答／產生」:模型名稱放在滑過的提示(與給螢幕閱讀器的文字)裡,問答、摘要、測驗、多格式輸出、問決策共用
    markdown-text.tsx      模型寫的 Markdown(問答的回答、AI 摘要)照格式顯示(粗體、引用、清單、標題、行內程式碼),解析在 `lib/markdown.ts`;純文字片段可以再轉一次(問答把 [n] 變成網路來源連結)
    password-input.tsx     密碼欄:`PasswordInput`(可以切換「顯示密碼」,登入、註冊、改密碼、刪除帳號都用)、`PasswordStrengthHint`(新密碼下方:規則與輸入時的強度,只是提示,規則由伺服器決定)
    protected-route.tsx
  context/
    auth-context.tsx  登入狀態;開啟或重新整理頁面時用 refresh token 的 cookie 換 access token 恢復登入(順便清掉舊版存在 localStorage 的 token);登出時通知伺服器作廢 refresh token、清 cookie(不等回應,連不上也照樣登出這裡),登出所有裝置(`logoutEverywhere`),刪除帳號(`deleteAccount`,成功後忘掉 access token、回登入頁)
  hooks/
    use-auto-follow.ts 自動跟隨的兩態狀態(跟隨中 / 已暫停)與 pause / resume
    use-job-socket.ts  WebSocket 訂閱單一 job 狀態更新:連上後第一則訊息送 access token;依關閉代碼決定重連——4401 換發 token 後重連(換發後仍被拒就不再試)、4404 不是你的 Job 不重連、4429 連線太多隔 30 秒、其他 3 秒
    use-media-playback.ts 把 media element 的播放狀態(時間、長度、是否暫停)同步成 React state;每次 timeupdate 都會 re-render,只給迷你播放器這種小元件用
    use-media-query.ts matchMedia 的 hook(工作區用它判斷桌面 / 手機版面)
    use-playback-continuity.ts 版面切換重新掛載 media element 時,把播放位置跟「是否正在播放」帶到新元素
    use-post-meeting.ts     會後處理:Job 完成時載入(能不能跑、最新一份紀錄、之前的紀錄),執行與重試行動提案,開始時帶瀏覽器時區,執行中每 3 秒輪詢,結束時重新載入用量;只採用最新一次請求的回應(慢回來的舊輪詢不會蓋掉較新的狀態);放在頁面這層,手機的 Studio Sheet 關著也照樣輪詢
    use-system-status.ts    登入前就要知道的系統狀態(GET /system/status:還沒有任何帳號、有沒有設定寄信),一次頁面載入只問一次、大家共用;還不知道時是 null(依賴它的東西先不顯示)
    use-notes.ts            筆記:Job 完成時載入,新增、改文字、刪除(失敗時 reject,由畫面提示並保留輸入);放在頁面這層,手機 Studio Sheet 關著也不會遺失
    use-translations.ts     譯文:Job 完成時載入各語言,要求翻譯(之後直接顯示那種語言的譯文),有翻譯中的就每 3 秒輪詢;逐字稿顯示什麼(原文 / 譯文 / 雙語)也在這裡,桌面的來源欄跟手機的 Source Sheet 一致;顯示中的語言每多翻好一批(或重翻完成,`completedAt` 變了)就重新取得片段的譯文,只用翻的時候的原文跟片段現在一樣的(`lib/current-translations.ts`);編輯逐字稿之後 ai-service 會在背景重翻改過的片段,前端看不到它開始,所以編輯後最多 60 秒也每 3 秒問一次,看到有變化就停;刪除一種語言(正在顯示它就回到原文);要求或刪除之前就送出的列表回來時丟掉(跟 use-quizzes 一樣),不會把刪掉的語言帶回來
    use-outputs.ts          多格式輸出:Job 完成時載入列表,要求產生(每次多一份),有「產生中」時每 3 秒輪詢,完成或失敗時重新載入用量;放在頁面這層(同測驗)
    use-speaker-insights.ts 講者數據的 AI 判斷(問題與打斷):Job 完成時載入,要求分析,分析中每 3 秒輪詢,完成或失敗時重新載入用量;放在頁面這層(同測驗)
    use-decisions.ts        決策紀錄:Job 完成時載入抽取紀錄與決策(會議、訪談轉錄完由 pipeline 自動抽,打開時可能已經在抽),要求抽出,抽取中每 3 秒輪詢,完成或失敗時通知(重新載入用量);新增、修改、刪除(失敗時讓表單保留輸入;之前送出的列表回來時丟掉,不會蓋掉剛做的修改)
    use-fact-check.ts       事實查核:Job 完成時載入標出主張的紀錄與主張,要求標出,查核勾選的主張(被拒時跳出原因,例如剩下的搜尋次數不夠),標出中或有主張查核中時每 3 秒輪詢,完成時通知(重新載入用量與本月剩下的搜尋次數);之前送出的回來時丟掉(跟 use-decisions 一樣)
    use-quizzes.ts          測驗:Job 完成時載入列表,產生測驗(每次多一份),有「產生中」時每 3 秒輪詢,產生完成或失敗時重新載入用量;剛要求的測驗不會被更早送出的列表請求蓋掉;放在頁面這層,手機的 Studio Sheet 關著也照樣輪詢
    use-summary-regeneration.ts 「重新產生摘要與章節」:呼叫 regenerate,RUNNING 期間每 3 秒輪詢摘要,IDLE 換上新內容並重新載入章節、FAILED 提示並保留舊內容;進頁面時已在跑也會接著等
    use-transcript-search.ts 逐字稿搜尋狀態(query、符合結果、選中的那個、上一個 / 下一個);輸入或切換結果時暫停自動跟隨;雙語時也搜每段的譯文
  lib/
    api-client.ts     fetch wrapper(auth header、401 refresh-and-retry、錯誤格式)+ refreshSession(用 cookie 換 access token,同時多個請求只換一次)+ requestSse(手動解析 SSE frame,問答 streaming 用)
    api.ts            對應 Gateway 每支 REST API 的函式
    link-token.ts      信裡連結的一次性 token(重設密碼、確認 email):從 `#` 後面讀出來後就從網址拿掉
    access-token.ts    access token 只放在記憶體(不放 localStorage);refresh token 在 httpOnly cookie,前端碰不到
    current-segment.ts 依播放時間找出「目前片段」(定義見 CONTEXT.md),二分搜尋
    download.ts        把瀏覽器產生的文字存成檔案下載(Blob + object URL + <a download>);開啟伺服器給的下載 URL(跨網域 presigned 連結靠回應的 Content-Disposition 下載)
    editor-keys.ts     就地編輯器(片段文字、講者名稱)共用的按鍵:Enter 儲存、Esc 取消,輸入法組字中不處理
    export-formats.ts  匯出格式轉換(不依賴畫面):`buildExportContent` 把工作區內容組成匯出輸入,每種格式是一個 `ExportFormat`(檔名結尾、MIME、render):TXT 純文字 / 含時間戳、SRT、VTT、Markdown 報告(大標是標題、沒有就檔名,有標題時多一行檔名;長度與建立時間、摘要、章節、可選筆記(依時間、沒釘時間的在後,`- [時間] 文字`,書籤寫「(書籤)」,多行縮排留在同一項)、兩位以上講者時的「講者數據」表格(發言時間、佔比、發言次數、最長一次,發言很少的標註;換人次數與無人說話的時間;分析過時加上「問題與打斷(AI 估計)」,過時時附註)、逐字稿,可選問答紀錄——只匯出已完成的回答,查過網路的那一題在時間戳之後列出「網路來源」(編號同回答裡的 [n]、Markdown 連結;沒查到時註明);摘要過時時附註)、決策的 Markdown(`DECISIONS_MARKDOWN_FORMAT` / `toDecisionsMarkdown`:大標「標題:決策」,每個決策一節,下面是理由、沒選的、提出者、時間點與原話;決策頁的 `toDecisionTimelineMarkdown`:大標「決策」、篩選、每場會議一節)、`withTranslation`(譯文取代每段文字,或雙語時接在原文下一行;沒翻到的、已清空的維持原文)、單獨的筆記 Markdown(`NOTES_MARKDOWN_FORMAT` / `toNotesMarkdown`:大標「標題:筆記」,有標題時多一行檔名,然後是同樣的筆記清單);事實查核的 Markdown(`buildFactCheckExport` 從標出的主張組成輸入,`toFactCheckMarkdown`,檔名結尾與 MIME 在 `FACT_CHECK_MARKDOWN`:大標「標題:事實查核」,有查核結果時「AI 依網路搜尋整理,請自行確認來源」(跟畫面一樣)、逐字稿改過時的過時提示;有結論的(含無法查核)依時間在「結論」,還沒查的列在最後的「還沒查核」,編號整份連續;每條是結論、類型、時間點與講者的原話、依據舊版逐字稿的標示、說明、來源(編號同說明裡的 [n]、Markdown 連結,沒標題時用網站名稱);無法查核的不寫說明,跟畫面一樣);測驗另外是 `toQuizMarkdown`(輸入是整份測驗而不是工作區內容,檔名結尾與 MIME 在 `QUIZ_MARKDOWN`):題目與選項在前,最後一節是解答、解說與依據的時間戳,過時時附註;共用規則——已清空片段不匯出、兩位以上講者才標示講者、文字格式時間戳 mm:ss / h:mm:ss、檔名取原始檔名去副檔名
    navigation.ts      離開這個網站到別的網址(連結帳號時到 Google / Notion);獨立出來讓測試可以替換(jsdom 不能換頁)
    local-time.ts      <input type="datetime-local">(瀏覽器時區、沒有時差)與 API 的 ISO 8601(含時差)互轉
    notes.ts           筆記的排序(依時間,沒有時間的在最後,同一時間依建立順序;跟伺服器一樣)、時間取到 0.1 秒、問答回答存成筆記的文字(拿掉網路來源的 [n],超過 2000 字截斷)、每個片段標哪些筆記(見 CONTEXT.md「筆記標記」)
    job-display.ts     Job 的顯示名稱(有標題用標題,否則檔名;規則只在這裡)、類型的中文名稱、決策頁用的會議日期(上傳的那一天)
    decision-links.ts  連到一個決策:它所在的 Job、打開「決策」到那一則(有時間點就跳到那裡);決策頁與取代的連結共用
    claims.ts          事實查核:主張落在哪個片段(片段的開始,兩位小數的誤差內)、結論與種類的中文名稱
    media.ts           檔案型別判斷、讀取媒體長度、格式化工具(長度、檔案大小、「9/26 14:07」這種簡短時間、列表與處理中頁面用的「2026/9/26 14:07」——不用瀏覽器語系的 toLocaleString,避免中文介面出現 AM/PM 與秒數)
    providers.ts       自有金鑰支援的廠商與顯示名稱;模型怎麼稱呼(「平台模型(…)」/「OpenAI · gpt-5」)、兩個模型是不是同一個
    usage-format.ts    用量數字的格式:token 數加千分位、轉錄秒數換成分鐘(Job 用量與本月用量共用)
    translation-languages.ts 譯文可以翻成的語言(跟後端一樣的清單)
    current-translations.ts  片段 id → 譯文,去掉原文已經改過(`sourceText` 跟片段現在的文字不一樣)還沒重翻的;逐字稿顯示與匯出共用
    password-strength.ts 密碼強度(不依賴畫面):少於 12 字元「太短」,長度為主、字元種類多(3 種以上)加分、只有一種字元或同一段重複扣分 →「弱／普通／強」
    output-formats.ts  多格式輸出:每種格式的名稱、社群平台與字數上限、貼文字數的算法(X 的中日韓字算兩個,跟 X 一樣)
    speaker-stats.ts   講者數據(不呼叫 AI,直接從逐字稿算):每位講者的發言時間、佔比、發言次數(同一位講者連續的片段算一次)、最長一次、平均,「發言很少」(少於平均每人的四分之一),整場換人次數與無人說話(片段之間超過 1 秒的空隙);已清空片段不算也不打斷;少於兩位講者時是 null
    speakers.ts        講者:依標籤查顯示名稱(名稱由後端決定,逐字稿與匯出共用)、是否只有一位講者(未清空片段中出現的講者 < 2 時所有講者顯示都隱藏)、要列出的講者(還有未清空片段的)、逐字稿只在換人的第一個片段顯示講者(已清空片段不顯示也不算換人)、依顯示順序從固定配色(index.css 的 --speaker-1…12,大型會議的講者也各不相同,超過 12 位才重複)取顏色
    staleness.ts       判斷摘要與章節、測驗、講者數據的分析、多格式輸出、決策是否過時(依據的逐字稿 revision < 逐字稿目前的 revision);Studio 與測驗卡片的提示、匯出的報告與測驗共用
    transcript-search.ts 逐字稿搜尋比對:比對顯示中的文字(顯示譯文時就是譯文;雙語時原文之後也比對譯文,結果標記在譯文裡)、英文不分大小寫、不跨片段;依片段分組
    markdown.ts        模型回答與摘要用到的一小部分 Markdown(不依賴畫面):`parseMarkdown` 讀成段落 / 標題 / 引用 / 清單 / 分隔線,`parseInline` 讀粗體 / 斜體 / 行內程式碼(記號要貼著字,「3 * 4 * 5」不算;串流中還沒收尾的 ** 先照打的顯示),其餘(表格、連結、HTML)維持純文字,不會產生任何 HTML;`markdownToPlainText` 去掉記號給一行預覽用(Studio 的摘要磚)
```

## 依賴套件弱點掃描

```bash
npm audit --omit=dev   # 會進到瀏覽器的依賴：要是 0
npm audit              # 含建置與測試工具（Vite、Vitest、shadcn CLI…），只在開發機與建置時執行
```

上線前、以及之後每個月或升級依賴時跑一次。高風險、嚴重的要升級（`npm audit fix`，不要用會降版的 `--force`），或在這裡寫清楚為什麼不影響。

最近一次結果（2026-10-03）：`npm audit fix` 修掉了 undici、qs、hono、js-yaml、fast-uri、ip-address 這些（都是 shadcn CLI 帶進來的）。`shadcn` 從
`dependencies` 移到 `devDependencies`——它是產生元件用的 CLI，程式只在建置時引用它的 `shadcn/tailwind.css`（`src/index.css`），不會進到瀏覽器。
之後 `npm audit --omit=dev` 是 0；完整的 `npm audit` 還剩 7 個高風險，全部來自 shadcn CLI → fast-glob → micromatch → `braces`
（大量巢狀大括號的 glob 會讓堆疊耗盡）。`braces` 目前沒有修好的版本，`npm audit` 建議的修法是把 shadcn 降到 1.0.0，不採用；它只在開發者自己跑
`npx shadcn add` 時、拿自己的檔案路徑執行，沒有外部輸入，不影響正式環境。
