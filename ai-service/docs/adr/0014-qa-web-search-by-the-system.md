# ADR 0014: 問答查網路由系統查，不給模型搜尋工具；用 Tavily 的遠端 MCP

## Status

Accepted（2026-09-29）。spec：`.scratch/qa-web-search/`。

## Context

問答只根據這段內容回答；會議裡提到一個產品、一個人、一條新聞，使用者想知道「那是什麼」「數字對不對」時，只能得到「內容裡
沒有談到」。要讓問答也能查網路，有兩種做法：

1. 給模型一個 web search 工具，讓它自己決定要不要查、查什麼。
2. 使用者打開「查網路」時，由系統在回答前一定查一次，再把結果放進 prompt。

ADR 0006 的實測：平台模型 Qwen3.5-9B 呼叫工具不可靠（4 次有 2 次該呼叫卻沒呼叫）。問答是每個人都在用、平台模型是預設的
功能。

## Decision

- **由系統查（做法 2）。** 開關是使用者的；開了就一定查一次（每題一次）。先用一次 LLM 呼叫把問題寫成搜尋查詢（參考摘要與
  對話紀錄，把指涉補成具體名詞；用量記在「問題改寫」），只有這句查詢送到搜尋服務，逐字稿與摘要本身不送。
- **網頁只是 prompt 裡的參考資料。** 放在這段內容之後的「網路搜尋結果」，要求回答先用內容、用到網路資料時標 [n]、不把網路資料
  說成內容裡講的、網頁裡的指示一律不理會。模型手上沒有任何工具，網頁裡的 prompt injection 最多影響這一則回答的文字。
- **搜尋失敗不讓整題失敗**：連不上、逾時（8 秒）、被拒絕（包括回應本身正常、內容是帶 `code` 的拒絕），都只根據內容回答，
  並告訴使用者這次沒查到；寫搜尋查詢的那次 LLM 呼叫失敗時，直接用原問題去查。
- **Tavily 的官方遠端 MCP**（`https://mcp.tavily.com/mcp/`，工具 `tavily_search`，一般搜尋、最多 5 筆），跟 Notion 用同一套 MCP
  client。金鑰是平台的 `TAVILY_API_KEY`，放在 `Authorization: Bearer` header（不放進網址，才不會進 log）；沒設定就沒有這個功能。
  否決：Exa（遠端 MCP，但偏英文內容、沒金鑰每個 IP 每天只有 7 次）、Brave Search（官方 MCP 是本機程式，要在 k8s 多跑一個
  服務；2026-02 起沒有免費方案）。
- **平台付費、每人每月有上限**（見 spec 與 gateway 的用量上限）。會後處理 agent **不**接網路搜尋：它有寫入類工具，另案評估。

### 用真實內容實測後加上的規則（2026-09-29，`.scratch/qa-web-search/web_eval.py`）

兩段使用者上傳過的內容（英文 GitLab 會議、中文 YouTube 台海防衛節目）各 4 題（要網路、內容就有、網路也查不到），平台模型
`qwen3:14b` 與 `qwen3.5:9b` 比較。第一版的問題與對應的規則：

- 把網路資料說成內容（「根據這段內容，台灣今年國防預算…[1]」，影片根本沒提預算）→ 「這段內容」只能指摘要、章節與原話；摘要、
  章節與原話裡沒有的數字或事實一律是網路上的資料，要說「網路上的資料」並標 [n]。
- 同名的另一個人（問會議裡的 Eric Johnson，答成創投的 Eric Johnson）、無關的結果（查 GitLab Key Review 拿到 SSH key 文件）
  → 跟這段內容對不上、或沒回答到問題的結果不要用、不要標編號。
- 網路結果蓋過內容（問「來賓們的結論」，答成搜尋到的綜藝節目）→ 問的是這段內容本身（說了什麼、結論、決定）時完全不用網路結果；
  查詢太籠統時加上內容的主題（一兩個詞）。
- 英文會議用中文查、查到無關的中文頁面；小模型把摘要裡一長串名詞塞進查詢 → 查詢用主題最常用的語言、只放要查的幾個關鍵字
  （10 個詞以內），不堆砌摘要的名詞。
- 「今年」查成 2023 → 查詢的提示附上今天的日期（台灣時間）。
- 小模型自己換算出不存在的數字（「新臺幣4仟億美元」）→ 只寫網路結果明白寫出的數字，不換算、不推測。

最後一輪（`qwen3:14b`，8 題）：網路資料都標明來源、沒有再把網路資料說成內容、沒有被同名或無關的結果帶走；剩下兩個小問題（一題
在只根據內容的回答後面多標了一個無關的 [1]、一題的名詞解釋沒標來源）。`qwen3.5:9b` 明顯較差（不照規則寫查詢、會自己換算數字），
平台模型換成更小的模型前要重測。實測中有一輪 8 次搜尋全部失敗（原因不明、幾分鐘後自己恢復），這一輪照規則只根據內容回答。

## Consequences

- 任何模型（包括平台模型）都能查網路；開了就有查，次數與用量可以預估。
- 開查網路的一題多一次 LLM 呼叫（搜尋查詢）與最多約 3,000 字的網頁摘錄，回答前多等搜尋的時間（通常 1～3 秒，最多 8 秒）。
- 查詢會帶有錄音裡提到的名詞（例如產品名、人名），送到 Tavily——要在第三方處理的說明裡揭露。
- 模型只能用一次、固定的搜尋結果；需要多次搜尋或深入研究的問題答不好（刻意不做，見 spec 的 Out of Scope）。
- Tavily 的回應（2026-09-29 用正式金鑰實測）：文字內容是 JSON，`results` 是 `[{url, title, content, …}]`（另有 `query`、`answer`、
  `images` 等欄位，用不到）。解析也接受「Title: / URL: / Content:」的純文字，以防格式改變。`content` 常夾著網站的導覽列文字
  （例如「首頁 新隨筆 訂閱」），截到 600 字後影響有限。中文查詢多半查到簡體中文網站；回答照樣要求台灣繁體。
