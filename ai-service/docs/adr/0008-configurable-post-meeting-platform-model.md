# ADR 0008: 會後處理的平台模型改成可設定

## Status

Accepted（2026-09-28）。局部取代 ADR 0006 的第 1 點（「會後處理不提供平台模型」）；ADR 0006 的其他決定不變。

## Context

ADR 0006 決定會後處理不提供平台模型：當時可用的免費選擇不是額度撐不住（Groq 免費層的 `gpt-oss-120b`），就是不可靠
（HF 上的 `Qwen3.5-9B` 有一半的時候不呼叫寫入工具）。結果是不想買 AI 金鑰的人完全用不到會後處理；各家的免費層也不夠
跑一次十幾次呼叫的 agent（Gemini 每個模型每天 20 次；OpenRouter 的 `:free` 模型每天 50 次、又常被上游限流，實際試用時就撞到 429）。

HF Inference Providers 上現在有 `Qwen/Qwen3.8-27B`：支援工具呼叫，deepinfra 的價格是每百萬 token 輸入 $0.20、輸出 $2.50，
照 ADR 0006 實測的量（大約 5 萬 token 輸入、5 千 token 輸出），一次會後處理約 US$0.02。用平台的 HF 金鑰實際打過一次
（關閉 thinking、給建立行事曆活動的工具）：它正確呼叫工具，「下週三下午兩點」也換算對了。

## Decision

- **會後處理的平台模型是一個部署設定**（ai-service 的 `AI_POST_MEETING_PLATFORM_MODEL`），**預設不提供**（空字串）。
  要不要替所有使用者負擔這筆費用，由部署的人決定。
- 有設定時，預設模型是平台模型的使用者也能跑會後處理，用這個模型走 HF 的 OpenAI 相容路由：平台的 HF 金鑰、關閉 thinking，
  跟一般的平台模型一樣。紀錄與用量寫 `platform` 加設定的模型 ID。
- 設定值是 HF 路由的模型 ID，可以帶 `:供應商` 後綴。要指定供應商：同一個模型在不同供應商上不一定支援工具呼叫
  （`Qwen3.8-27B` 的 featherless-ai 就沒有標示），HF 預設挑最快的供應商，挑到不支援的會壞。本機開發設成
  `Qwen/Qwen3.8-27B:deepinfra`。
- 預設模型是自有金鑰的使用者照舊用自己的模型；自有金鑰失敗時照舊直接失敗，不改用平台模型。
- 一般生成（摘要、章節、問答、測驗）的平台模型不變（`AI_HF_CHAT_MODEL`）。平台模型仍然是「每種用途固定一個、使用者
  不能挑」。

## Consequences

- 費用與額度算在平台的 HF 金鑰上，跟摘要、章節、問答、embedding 共用。HF 免費帳號每月只有 US$0.10，大約只夠跑 5 次
  會後處理；額度用完之後，所有用平台模型的功能都會失敗，直到儲值。正式開放給所有人前，要先有用量上限。
- `Qwen3.8-27B` 還沒用 ADR 0006 的三段實測會議驗證過品質（當時它在 Groq 上被額度卡住，沒跑完）。品質不夠時換設定值即可，
  不用改程式。
- 本機跑的模型（例如 Ollama）也能用同一個設定接進來，只要它提供 OpenAI 相容路由——但那要另外設定 HF 路由的網址，
  不在這次的範圍。
